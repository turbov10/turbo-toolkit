# Calculator

A polished calculator that runs as a **WeChat Mini Program**, in the **browser**, and as a **native macOS / Windows desktop app** — from a single React + TypeScript codebase, built with [Taro 4](https://taro-docs.jd.com/) and [Tauri 2](https://tauri.app/).

```
┌─────────────────┐  ┌──────────┐  ┌────────────────┐
│ WeChat Mini App │  │ Browser  │  │ macOS / Win app│
│   (taro weapp)  │  │ (H5)     │  │  (tauri 2)     │
└────────┬────────┘  └────┬─────┘  └──────┬─────────┘
         └────────┬───────┘────────┬──────┘
                  ▼                ▼
            ┌──────────────────────────┐
            │  src/  (React + TS)     │
            │  + src-tauri/ (Rust)    │
            └──────────────────────────┘
```

## Highlights

- One component tree renders on all three targets (Taro's `<View>` / `<Text>` / `<Button>`).
- Hand-written, `eval`-free expression evaluator with `+ − × ÷`, parens, decimals, percent, sign toggle.
- Modern dark UI: gradient background, glass display, color-coded keypad, press-scale feedback, optional haptic on mobile.
- Dependencies pinned to the **latest stable** versions (no `^`, no `~`, no `@latest`).
- Minimal imports — no UI kit, no Tailwind, no boilerplate.

> **Version note**: Taro 4.2.0's peer dep is `react ^18`, and Taro's generated
> `app.boot.js` calls `ReactDOM.render` (removed in React 19). So `react` and
> `react-dom` are pinned to **18.3.1** — the latest stable React that
> Taro 4.2.0 actually supports. Every other dep is at the latest stable.
>
> A postinstall script (`scripts/patch-taro-webpackbar.mjs`) patches
> `@tarojs/webpack5-runner`'s `BaseConfig.js` to drop the bundled `webpackbar`
> plugin (which stores legacy options on `this.options` and breaks
> `webpack.ProgressPlugin`'s schema validation in webpack ≥ 5.97) and replace
> it with a vanilla `webpack.ProgressPlugin` using the new API. The patch is
> idempotent and re-applies on every `pnpm install`.

## Requirements

- **Node.js ≥ 20** (the user has 26.x — fine).
- **pnpm ≥ 9** (the user has 11.x).
- For the desktop build: **Rust toolchain** (`rustup`) and platform deps.
  - macOS: `xcode-select --install` then `rustup target add aarch64-apple-darwin x86_64-apple-darwin`
  - Windows: [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) + `rustup default stable` + WebView2 (preinstalled on Win 11).

## Quick start

```bash
cd calculator
pnpm install                  # installs JS deps (may need to approve build scripts once)
pnpm gen:icons                # generates src-tauri/icons/* (only needed once, or to refresh)

# --- development ---
pnpm dev:weapp                # watch mode for WeChat mini program → load dist/ in WeChat DevTools
pnpm dev:h5                   # watch mode for H5 → open http://localhost:10086

# --- production builds ---
pnpm build:weapp              # outputs dist/ for WeChat DevTools import
pnpm build:h5                 # outputs dist/index.html + assets (used by Tauri too)
pnpm typecheck                # tsc --noEmit
```

### One-time `pnpm install` quirk

On first install pnpm 11 may ask to approve a few native postinstalls
(`esbuild`, `@swc/core`, `core-js`, `@parcel/watcher`, `@tarojs/binding`, `@tarojs/cli`).
The `pnpm-workspace.yaml` in this repo already lists them, so a re-run of
`pnpm install` after cloning is enough — no interactive prompt should appear.

## Scripts

| Script              | What it does                                                                |
| ------------------- | --------------------------------------------------------------------------- |
| `pnpm dev:weapp`    | Taro watch build → WeChat mini program (open `dist/` in WeChat DevTools).   |
| `pnpm dev:h5`       | Taro watch build → H5 dev server on `http://localhost:10086`.              |
| `pnpm build:weapp`  | One-shot production build for WeChat (outputs to `dist/`).                  |
| `pnpm build:h5`     | One-shot production build for H5 / Tauri (outputs to `dist/`).              |
| `pnpm tauri:dev`    | Build H5 then launch Tauri dev window (HMR via `devUrl`).                   |
| `pnpm tauri:build`  | Build H5 then build native installer / `.app` / `.exe` for the host OS.    |
| `pnpm typecheck`    | `tsc --noEmit` against the project `tsconfig.json`.                        |
| `pnpm gen:icons`    | Generate the source PNG, then derive every Tauri icon from it.              |

> `pnpm dev:tauri` and `pnpm build:tauri` are convenience wrappers that run
> `pnpm build:h5 && tauri …`. They exist so you can stay on `pnpm`; you can
> also call `tauri` directly via `pnpm tauri …` or `npx @tauri-apps/cli …`.

## WeChat Mini Program — detailed publish flow

The whole flow lives in two tools: **WeChat DevTools** (local IDE) and
**WeChat MP Console** (web admin at <https://mp.weixin.qq.com>).

### 1. Get an AppID (one-time)

1. Open <https://mp.weixin.qq.com> and click **Register now** (右上角"立即注册").
2. Choose account type **小程序** (Mini Program).
3. Fill in email, password, and verify the email.
4. In the registration form, pick **主体类型**: 个人 (individual) or 企业/媒体/政府 (organization). The "individual" path needs real-name ID verification; the "organization" path needs a business license.
5. After login, open **开发管理 → 开发设置** (Manage → Dev Settings).
6. Copy the **AppID(小程序ID)** — a `wx…` string. Also note the **AppSecret(小程序密钥)** (you can generate one; keep it private).

### 2. Plug the AppID into the project

1. In `calculator/project.config.json`, replace the placeholder:
   ```json
   "appid": "touristappid"   →   "appid": "wxYOUR_REAL_APPID"
   ```
2. (Optional) If you do not want to commit your AppID, also create `calculator/project.private.config.json` and override `appid` there — IDE merges it on top of the public file. This file is git-ignored by convention; the template ships a generic version you can edit locally.
3. In `calculator/src/app.config.ts` keep the `pages` list in sync with the pages you actually ship.

### 3. Install WeChat DevTools

1. Download from <https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>.
2. Install and sign in with the WeChat MP account that owns the AppID (or a developer-绑定的微信号 — see step 4).

### 4. Bind developer /体验者 WeChat accounts

In **WeChat MP Console → 成员管理 → 开发者 / 体验者**:

- **开发者** (developer): can upload code via DevTools.
- **体验者** (tester): can open the "体验版" (trial version) from WeChat on their phone.

Add the relevant WeChat IDs (手机号 / 微信号) and confirm the invite on the user's phone.

### 5. Run a production build

```bash
cd calculator
pnpm install
pnpm build:weapp
```

This produces `calculator/dist/` containing `app.js`, `app.json`, `app.wxss`, `pages/`, `project.config.json`, etc. — exactly the format WeChat DevTools wants.

### 6. Import the project in WeChat DevTools

1. Launch WeChat DevTools.
2. **小程序 → + → 导入项目** (Mini Program → + → Import Project).
3. **目录**: pick `calculator/dist/` (the freshly built folder).
4. **AppID**: pre-filled from `project.config.json`; override if needed.
5. **项目名称**: any friendly name (e.g. "Calculator").
6. **后端服务**: leave as **不使用云服务** (no cloud) unless you add one.
7. Click **导入**.
8. DevTools compiles, opens the simulator on the left, and shows the console on the right — you should see the dark calculator UI.

### 7. Debug on a real phone (optional but recommended)

1. In DevTools, click the **预览 / 自动预览** button (top toolbar, the QR-code icon). It generates a QR code valid for ~30 minutes.
2. The bound **体验者** scans it with WeChat → the trial mini program opens on their phone.
3. Fix any layout/runtime issues reported in the DevTools console or in the WeChat `vConsole` panel on the device.

### 8. Upload the code to the MP backend

1. In DevTools, click **上传** (Upload, the cloud arrow icon in the top toolbar).
2. Fill in **版本号** (e.g. `0.1.0`) and **项目备注** (a short changelog, required).
3. Click **上传**. DevTools shows success and prints the version number.
4. Go to <https://mp.weixin.qq.com> → **版本管理** (Manage → Version Management). You should see a new row under **开发版本** (development version) with the version you just uploaded.

### 9. Submit for review

1. In **版本管理 → 开发版本**, find your version, click **提交审核** (Submit for Review) on the right.
2. Fill in the **审核表单**:
   - 功能页面截图 (screenshots of each page — use the simulator)
   - 测试账号 (if your mini program requires login; not needed for this calculator)
   - 类别标签 (category tags)
3. Read the **小程序平台运营规范** and confirm compliance. The calculator is purely functional — no user-generated content, no login, no payments — so review typically clears in a few hours.

### 10. Release

1. After review, the version moves to **审核版本** (review version) with status **审核通过**.
2. Click **发布** (Release). The version becomes the **线上版本** (live version) and is searchable in WeChat within ~5 minutes.

### 11. Subsequent updates

The cycle is just:

```bash
pnpm build:weapp
# in DevTools: 上传
# in MP Console: 开发版本 → 提交审核 → 发布
```

### Common publishing gotchas

| Symptom | Fix |
| --- | --- |
| "AppID 不匹配" on upload | The AppID in `project.config.json` must match the logged-in MP account. |
| "请先在微信公众平台配置服务器域名" | Only needed if you call network APIs. The calculator is offline, so this warning is safe to ignore. |
| "页面路径未在 app.json 中声明" | Every page you add must be listed in `src/app.config.ts`'s `pages` array. |
| Blank simulator after import | You probably pointed DevTools at the source folder instead of `dist/`. Re-import and pick the **built** `dist/`. |
| `pnpm dev:weapp` keeps rebuilding forever but DevTools doesn't update | DevTools must be pointed at the **built** `dist/` folder, not the source. |

## macOS / Windows desktop (Tauri 2)

### First-time setup

```bash
# macOS
xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin

# Windows (PowerShell, in an elevated prompt)
# 1. Install "Microsoft C++ Build Tools" from the Visual Studio page
# 2. Install Rust via https://rustup.rs/
# 3. WebView2 is preinstalled on Windows 11
```

Then in this folder:

```bash
pnpm install
pnpm gen:icons      # one-time; regenerate any time you change the source PNG
pnpm build:h5       # populates dist/ (Tauri reads from here)
```

### Development with live reload

```bash
pnpm tauri:dev
# Tauri boots the H5 build, opens a 420x760 window titled "Calculator".
# The H5 dev server runs at http://localhost:10086 — the Tauri webview
# loads it through the devUrl hook in tauri.conf.json.
```

### Production build

```bash
pnpm tauri:build
# macOS:   src-tauri/target/release/bundle/macos/Calculator.app
#                            + dmg/  (drag-install image)
#                            + macos/Calculator.app
# Windows: src-tauri/target/release/bundle/msi/Calculator_0.1.0_x64_en-US.msi
#                            + nsis/Calculator_0.1.0_x64-setup.exe
```

The `Calculator.app` / `Calculator.exe` runs entirely offline — no Chrome, no Node, no Docker — and the app can be closed via the standard window controls (red dot on macOS, ✕ on Windows) or `Cmd/Alt+F4`.

### Cross-compiling (advanced)

- From **macOS** you can build a Windows installer by adding `x86_64-pc-windows-msvc` to rustup and running `pnpm tauri build --target x86_64-pc-windows-msvc`. A full MSVC toolchain on macOS needs [osxcross](https://github.com/tpoechtrager/osxcross) — usually easier to do the Windows build on a Windows machine.
- From **Windows** you can build a macOS app only via the [Tauri iOS tooling](https://tauri.app/distribute/app-store/) — not a common flow.

## Architecture notes

### Calculator engine (`src/lib/calc.ts`)

```
string  →  tokenize()  →  tokens
tokens  →  toRPN()     →  RPN tokens  (shunting yard, parens respected)
RPN     →  evalRPN()   →  number      (no eval, no Function())
```

- Numbers: integer or decimal, only one `.` per number segment.
- Operators: `+`, `-` (and `−`), `*`, `×`, `/`, `÷`, `·`. Unicode variants are normalized to ASCII inside the tokenizer.
- Unary minus: `(-5)`, `-5+3`, `5*-2` all work.
- Auto-closing parens: `(1+2` + `=` → evaluates as `(1+2)`.

### UI state machine (`src/lib/useCalculator.ts`)

`useCalculator` exposes a single `press(key: Key)` function and a `state` object. Every key — digit, operator, paren, AC, ⌫, ±, %, = — is one switch case. The reducer enforces invariants like "no second decimal in a number", "operator replaces operator", "closing paren needs an open one".

### Cross-target component tree

`<View>`, `<Text>`, and `<Button>` come from `@tarojs/components`. On H5 they render to `div`, `span`, `button`; on WeChat they render to `<view>`, `<text>`, `<button>`. The SCSS files are compiled by Taro's PostCSS pipeline (`postcss-pxtransform` converts `px` to `rpx` on the mini program side).

### Tauri window

`src-tauri/tauri.conf.json` declares one window (label `main`, 420×760, resizable). `frontendDist: "../dist"` points at the Taro H5 build. `beforeDevCommand` / `beforeBuildCommand` chain `pnpm build:h5` so a single `tauri dev` / `tauri build` is enough.

`src-tauri/capabilities/default.json` grants only the `core:default` permission set — the calculator does not need filesystem, network, or shell access, so the surface stays minimal.
